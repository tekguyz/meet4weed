# Meet4Weed — domain language

The words this codebase uses, and what each one means here. Created lazily as
terms resolve, per `docs/agents/domain.md`. If a name below and a name in the
code disagree, the code is wrong.

Rules and their reasons live in `CLAUDE.md`. This file is only vocabulary.

---

## Sesh

A gathering hosted by one verified member, usually at their home. Table
`public.seshes`.

**Not "session".** That word already means an auth session in
`lib/supabase/session.ts`, and one word meaning two things in one codebase is
how a wrong `session` gets passed to the wrong function. The spec uses "sesh"
throughout (§5, §6).

A sesh is `open` or `cancelled`. There is no `full` state — fullness is
`approved_count` against `capacity` — and no `ended` state, because whether a
sesh has finished is a question about `starts_at` and the clock.

**Cancelling is final.** There is no un-cancel. Un-cancelling would hand a
private address back to a guest list that had already moved on.

## Host

The member who created a sesh. `seshes.host_id`. A host is never a guest of
their own sesh and holds no RSVP row for it.

## Capacity

The number of **guests** a host will accept. The host is not one of them, so
"6 spots" means six people can be approved.

## Exact location

The five private columns on a sesh: `exact_lat`, `exact_lng`, `address_line`,
`unit_note`, `gate_code`.

`authenticated` holds **no SELECT grant** on any of them, so naming one in a
query fails the whole statement with `42501`. A wildcard is not an exception —
`select *` names every column and fails too, which is why
`lib/sesh/queries.ts` lists its columns by hand.

The only way to read them is `public.sesh_address()`.

## Fuzzy point, fuzzy circle

The public stand-in for the exact location: `fuzzy_lat`, `fuzzy_lng`, and
`fuzzy_radius_m` (400, so the circle is about half a mile across). Written by a
trigger, never by a host.

The offset is a **fixed function of the address**, not a random number per
sesh. One home always produces one circle. A host running ten seshes therefore
gives nobody ten samples to average back to the house.

The offset is between **500 feet and a quarter of a mile**. The floor exists because a host
cannot reshuffle their own circle — it is a function of their address — so the
guarantee replaces the reshuffle: the circle is never centred on the door.

The exact point is always inside the circle that gets drawn. The circle is
honest, not decorative.

## Pepper

32 random bytes in `private.fuzz_pepper`, generated by the migration and read
by nothing but security-definer functions. It is what makes the fuzzy offset
unguessable: the sesh id is public, so an offset derived from the id could be
subtracted back off.

It is never rotated. Rotating it would move every circle in the app at once.

## Unlock

The moment an approved guest can read the exact location. Decided entirely by
`private.can_see_address()`, never by a screen.

Two branches:

- **Host** — no time check, no cancelled check. A host must be able to load
  their own edit screen after the sesh has started or been cancelled.
- **Guest** — an `approved` RSVP, the sesh still `open`, and within 12 hours of
  the start. Both branches also require the caller's own card to still be
  valid, so a guest whose card lapses loses the address even though the host
  approved them.

An empty result is the **locked state**. It is not an error, and a screen
renders the locked card from it rather than deciding anything itself.

## Wipe

What the app forgets seven days after a sesh starts: the exact location, the
bring list, the invites and the invite claims. The title, the times, the area
name and the fuzzy circle stay, so a member keeps a history of where they went
without the app keeping who was in the room.

Different from the unlock ending at 12 hours: that is about who may read the
data, this is about the data no longer being there.

One function, `public.sesh_address_reaper()`, and one schedule. The name is
narrower than the job for a reason the migration header states. It rides inside
the daily expiry sweep; there is no second cron entry.

`rsvps` is deliberately **not** wiped, and nothing has decided whether it
should be.

## Area name

A short public label for roughly where a sesh is — "Riverside", "South Tampa".
Looked up from the **fuzzy** point, never the exact one, so nothing private
leaves the app.

## On deck

The bring list for one sesh. Table `public.contributions`, one row per thing
per member. **Not "inventory" and not "stash"** — nobody is offering anything,
they are saying what they are bringing to a room they were already invited to.

Three states are three row shapes: `strain` (a name and a strain type), `item`
(a name), and `none` (the member is bringing nothing, said out loud). A
trigger keeps `none` and the other two exclusive, so nobody is ever in both
states and no screen has to pick one to hide.

Losing `approved` takes your rows with you. A host is never left counting on
something nobody is bringing.

## Invite

A link a host hands somebody. Table `public.invites`.

**The token is never stored.** The row holds `sha256(token)` only, and
`token_hash` carries no SELECT grant for `authenticated`, so a host's own panel
cannot rebuild the link either. The host sees it once, in the reply to
`mint_invite()`.

An invite lets somebody **ask**. It never admits them. Redeeming writes a
claim, never an RSVP, and **the host still approves by hand.**

**A use is spent by a signed-in person pressing a button, never by a page
load.** `invite_preview()` reads and changes nothing; `redeem_invite()` spends.
Group-chat link previews fetch a pasted URL, and a one-use link that spent
itself on that fetch would be dead before a human saw it.

## Claim

`public.invite_claims`: this member walked through that link. It is **never**
an RSVP and **never** an input to `private.can_see_address()`.

A claim is permanent until the wipe takes it. Only being denied or kicked ends
what it lets somebody see.

## Unlisted

`seshes.visibility = 'unlisted'`: absent from the feed, the map and search.
Readable by the host, by anybody holding a live RSVP, and by anybody holding an
invite claim.

It is not a secret sesh — the same RLS decides everything else about it — it is
a sesh that does not advertise. Every existing row is `listed`, and `listed`
behaves exactly as a sesh behaved before the column existed.

**The exclusion lives in the policy, never in a query.** `lib/sesh/queries.ts`
kept the `where` clauses it already had. The feed, the map and search cannot
get this wrong, because none of the three knows the rule exists.

## Active member vs. browsing member

Two different gates, and mixing them up either locks an expired member out or
lets them host.

- `private.is_active_member` — status `verified` **and** a card date that has
  not passed. Every **write** uses this.
- `private.can_browse` — status `verified` **or** `expired`. Every **read**
  uses this, because an expired member is read-only rather than shut out.
